# 첫 유료 고객 검증

## 현재 사실과 가설

- 사실: 표준 양식에 대한 로컬 시제품을 제작한다.
- 가설: 소규모 판매자가 반복 주문 정리 자동화에 15만 원을 지불할 수 있다.
- 미확인: 고객군, 판매 채널별 원본 양식, 실제 절약 시간, 유료 전환, 유지보수 비용.
- 고객 접촉·판매 등록·결제·도메인 구매는 아직 하지 않았다.

시연 성공은 수요 검증이 아닙니다. 칭찬이나 무료 사용 의향보다 **샘플 제공과 유료 범위 합의**를 다음 단계의 근거로 삼습니다.

## 첫 7일 실험

| 시점 | 행동 | 기록할 결과 |
|---|---|---|
| 1일차 | 로컬 시연 확인, 제안 범위와 가격 검토 | 정상·취소·오류 사례를 설명할 수 있는가 |
| 2~3일차 | 연결 가능한 소규모 판매자 5명에게 개별 문의 | 반복 작업 유무, 빈도, 소요 시간 |
| 3~4일차 | 관심 있는 상대에게 익명 샘플 요청 | 실제 샘플 제공 수 |
| 4~5일차 | 한 사람의 샘플과 기대 결과를 비교 | 지원 범위와 예외를 합의할 수 있는가 |
| 5~7일차 | 고정 범위 유료 시범 제안 | 확정된 유료 의뢰 수와 거절 이유 |

이는 실행 제안입니다. 이미 5명에게 연락했거나 고객이 확보되었다는 의미가 아닙니다. 첫 5명은 작은 탐색 표본이며, 응답이 없다고 전체 시장에 수요가 없다고 단정하지 않습니다.

## 먼저 물어볼 질문

1. 매주 또는 매월 반복해서 정리하는 파일이 있나요?
2. 파일을 받아 어떤 순서로 처리하나요? 예시 결과를 보여줄 수 있나요?
3. 한 번에 얼마나 걸리며, 어떤 실수가 가장 불편한가요?
4. 엑셀 함수나 기존 도구로 해결하지 못하는 부분은 무엇인가요?
5. 입력 양식 1종을 자동화하는 작업을 15만 원에 맡길 의향이 있나요?

처음부터 기능 목록을 제시하기보다 실제 작업과 비용을 듣습니다. 불필요한 고객 연락처·주문 개인정보는 수집하지 않습니다.

## 반응별 다음 행동

- **같은 작업을 반복하는 고객이 있고 샘플을 준다:** 그 양식에만 맞춘 변환을 만든다.
- **유료 범위를 합의한다:** 정해진 수정 횟수와 납품 기준으로 첫 작업을 진행한다.
- **좋다고 하지만 파일·구매 의향이 없다:** 개발 기능을 늘리지 말고 불편의 강도와 가격을 다시 확인한다.
- **모든 고객의 요구가 다르다:** 당분간 맞춤 작업으로 판매하고 공통 부분만 재사용한다.
- **독립 고객 3명 이상이 같은 기능에 돈을 낸다:** 다운로드 상품 또는 웹 서비스화를 검토한다. 이 숫자는 내부 의사결정 기준이지 성공을 보장하는 시장 법칙이 아니다.

고객명 대신 임의 식별자를 사용합니다. 초기 행은 비어 있으며, 관측하지 않은 수치를 채우지 않습니다.

## 추가 비용을 쓰는 시점

도메인은 이름과 판매 방향이 정해지고 공개 시연이 필요할 때 구매합니다. 첫 시연은 로컬 화면 공유로 할 수 있습니다. 파일을 서버에 보내지 않는 정적 도구이므로, 초기에는 Proxmox의 DB·로그인·결제 서버를 구축할 이유가 없습니다.

기존 Android 개발자 등록비 때문에 새 프로젝트의 도메인·서버·광고비를 먼저 집행하지 않습니다. 다음 지출은 그 지출로 검증할 질문이 있을 때 결정합니다.

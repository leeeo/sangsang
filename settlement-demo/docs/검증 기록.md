# 시제품 검증 기록

## 검증 범위

표준 주문 양식으로 동작하는 로컬 시제품을 검증합니다. 고객 수요, 쇼핑몰별 실제 원본 파일, 결제, 운영 서버, 유료 고객 확보를 검증한 기록이 아닙니다.

## 자동 테스트와 빌드

- `bun test`: **36개 통과, 실패 0개**.
- 범위: 완료·취소 합산, 앞자리 0 보존, 정수 금액, 날짜, 과도한 할인, 중복 주문, 빈 파일, 행·파일 수 한도, 잘못된 형식, 수식 입력 차단, 다중 파일 병합, UTF-8 CSV, XLSX 다운로드 내용.
- `npx --yes pnpm@10.34.5 build`: TypeScript 검사와 Vite 프로덕션 빌드 통과.
- TypeScript 검사 대상에는 `src`, `tests`, `scripts/export-fixtures.ts`, `vite.config.ts`를 포함합니다.
- TypeScript AST 점검: 명시적 `any`, 비상수 타입 단언, non-null 단언 없음. 각 TypeScript 구현 모듈은 코드 250줄 이내입니다.

첫 CSV 테스트에서 SheetJS의 문자열 입력 형식이 지정되지 않은 문제가 발견되었습니다. CSV에는 `type: "string"`을 명시하도록 수정한 후 전체 36개가 통과했습니다.

## 실제 브라우저 검증

서버를 실행한 상태에서 별도 Chrome 창을 사용합니다. 공유 wmux 캡처 문제 후 **사용자가 별도 Chrome/Playwright 검증을 명시적으로 승인**했습니다. 개인 로그인 프로필은 사용하지 않으며, 검증이 끝나면 검증용 창과 임시 브라우저 컨텍스트를 닫습니다. 이 컴퓨터에 Chrome이 설치되어 있어야 합니다.

```sh
npx --yes pnpm@10.34.5 preview
# 다른 터미널에서:
npx --yes pnpm@10.34.5 test:browser
```

- **1280px / 390px**에서 초기 상태, 가상 샘플, XLSX 다운로드·재업로드, CSV 업로드, 중복 오류, 6개 파일 드롭 차단, 초기화를 검증합니다.
- Playwright의 `setInputFiles`와 브라우저의 `DataTransfer`로 실제 파일 입력·드롭 이벤트 및 계산 버튼을 거칩니다. 코어 함수를 직접 호출해 화면 테스트를 대체하지 않습니다.
- DOM 변경을 관찰한 뒤 동작을 시작하며, 완료 상태를 기다리는 데 고정 sleep이나 폴링을 사용하지 않습니다.
- 클릭 전에 실제 다운로드 이벤트를 구독하고, 다운로드한 파일을 디스크에 저장해 다시 읽습니다. XLSX의 `정산요약!B9 = 149400`을 확인합니다.
- 새 파일을 고르면 기존 결과와 다운로드가 즉시 비활성화됩니다.
- 중복 주문은 문제 1건으로 표시되고, 오류 제목에 포커스가 이동하며 다운로드가 차단됩니다.
- 화면 전체의 가로 넘침을 검사합니다. 주문 표만 자체 가로 스크롤을 허용합니다.
- 페이지 JavaScript 오류는 0건이며, 각 너비에서 발생한 요청 21개는 모두 로컬 서버의 GET입니다. 업로드 요청이나 외부 전송은 없었습니다.

출력은 `evidence/browser-results.json`, `evidence/screenshots.json`, PNG 캡처와 브라우저 다운로드 XLSX입니다. `evidence/`는 재생성 가능한 로컬 검증 자료이므로 Git에서 제외합니다.

## 도구 제약과 수정 내역

- 공유 wmux에서는 숨겨진 탭 연결, 최소화된 창, 캡처 시간 초과·검은 화면·합성 반복을 확인했습니다. 설치된 wmux 자체는 수정하거나 재시작하지 않았습니다.
- 최종 증거는 승인된 독립 Chrome에서 생성한 `screenshots.json`의 **뷰포트별 PNG**만 사용합니다. 이전 wmux 캡처는 판정 근거가 아닙니다.
- 실제 렌더링을 보고 통계를 2열로 배치하고, 제목의 두 구절을 분리했으며, 주문번호·날짜·상품명·원본 파일명이 과도하게 줄바꿈되지 않도록 열 폭을 조정했습니다.
- 코드 검토에서 파일 6개 이상 드롭 시 실제 입력에는 5개만 들어가는 표시 불일치를 발견했습니다. 입력과 표시 목록을 일치시켰으며, 6개 전체를 받은 뒤 계산 단계에서 한도 오류로 차단하는 것을 실제 브라우저에서 확인했습니다.
- 제공된 별도 TypeScript 규칙 검사기는 TypeScript 7의 `unstable` API를 요구해 이 프로젝트의 TypeScript 5.9.3에서 실행되지 않았습니다. 설치된 컴파일러의 AST 점검과 `tsc`로 대체했습니다.
- CSS/JSON용 Biome 언어 서버는 설치되어 있지 않습니다. 해당 LSP 검사는 실행하지 못했으며, Vite 빌드·실제 렌더링과 소스 검토로 확인합니다.
- 빌드 시 Zod 배포 코드의 주석 위치에 대한 Rollup 경고 2건이 있습니다. 의존성 코드를 수정하거나 경고를 숨기지 않았으며 빌드는 성공했습니다.

## 독립 검토 결과

- **금액 계산·입력·다운로드 안전성: PASS.** 실제 코어와 테스트를 검토했으며 차단할 결함은 없었습니다. 파일 드롭 표시 불일치는 수정하고 실제 브라우저로 검증했습니다.
- **화면 구조·기능 일치: PASS.** 최신 캡처 18개와 UI 소스·디자인 토큰·실행 기록을 대조했습니다. 실제 DOM 기반이며 상태와 금액이 실행 결과에 일치합니다.
- **한글·반응형 시각 검토: PASS.** 최신 캡처 18개를 모두 확인했습니다. 캡처된 상태에서 겹침, 의도하지 않은 페이지 가로 넘침, 한글 글리프 누락, 검은 화면·잘못된 합성은 발견하지 못했습니다.

차단하지 않는 후속 개선 후보로는 모바일 표의 시각적인 좌우 스크롤 안내, 스크롤 중 떠 있는 내비게이션 주변 여백, 장식 점의 색상과 디자인 문서 규칙 사이의 표현 불일치가 있습니다. 이번 시제품의 동작을 막는 항목은 아니며 추가 구현하지 않았습니다.

검증 브라우저는 이 컴퓨터의 Chrome이며 실제 재계산 도구는 Microsoft Excel입니다. Firefox·Safari, 다른 스프레드시트 프로그램, CP949 CSV와 쇼핑몰별 실제 파일을 지원한다고 주장하지 않습니다. 실제 고객 파일과 유료 의사는 다음 고객 검증 단계에서 확인해야 합니다.

# 정산 한 장

소규모 판매자의 반복적인 주문 정리를 유료 자동화 작업으로 제공할 수 있는지 확인하기 위한 **로컬 시제품**입니다. 고객 수요, 실제 거래, 플랫폼별 연동은 아직 검증하지 않았습니다.

## 실행

이 폴더에서 Node.js 22.12 이상과 Bun을 사용합니다.

```sh
npx --yes pnpm@10.34.5 install --frozen-lockfile
npx --yes pnpm@10.34.5 dev
```

브라우저에서 http://127.0.0.1:8796 을 엽니다. 파일은 브라우저 메모리에서 처리하며 서버로 업로드하거나 브라우저 저장소에 보관하지 않습니다. 새로고침하면 작업 상태가 사라집니다. 정적 화면 파일을 제공하는 개발 서버만 필요합니다.

```sh
bun test
npx --yes pnpm@10.34.5 build
npx --yes pnpm@10.34.5 preview
```

`dev`와 `preview`는 같은 포트를 사용하므로 동시에 실행하지 않습니다.

## 1분 시연

1. **가상 샘플로 계산**을 누릅니다. 실제 XLSX 파일을 생성한 뒤 업로드와 동일한 경로로 읽습니다.
2. 가상 주문 6건, 완료 5건, 취소 1건을 확인합니다.
3. 완료 상품 판매액 152,000원 − 할인 7,000원 + 배송비 12,000원 − 수수료 7,600원 = **예상 정산액 149,400원**을 확인합니다.
4. 결과 XLSX를 내려받습니다. `정산요약`, `정산내역`, `사용안내` 시트가 있습니다.
5. 샘플 양식을 내려받아 주문번호를 중복시킨 후 다시 올립니다. 문제 파일과 행이 표시되고 결과 다운로드는 차단되어야 합니다.

샘플 상품명·주문번호·금액은 모두 시연용으로 만들었습니다. 실제 판매 실적이 아닙니다.

## 지원하는 입력

`.xlsx` 또는 **UTF-8** `.csv`, 파일당 5 MiB 이하, 최대 5개, 전체 주문 10,000행 이하입니다. 데이터가 있는 시트는 파일당 하나여야 합니다.

첫 행의 열 이름과 순서를 아래와 같이 맞춥니다.

| 열 | 입력 규칙 |
|---|---|
| 주문번호 | 텍스트, 전체 파일에서 유일. `0001` 같은 앞자리 0 보존 |
| 주문일 | 텍스트 `YYYY-MM-DD`, 실제 존재하는 2000~2100년 날짜 |
| 상품명 | 1~120자 텍스트 |
| 수량 | 1~10,000의 정수 |
| 판매단가 | 상품 한 개의 가격, 0~1,000,000,000원 정수 |
| 할인액 | 주문 전체 할인액. 상품 판매액을 초과할 수 없음 |
| 배송비 | 고객에게 받은 해당 주문의 배송비 |
| 수수료 | 해당 주문에 차감할 수수료 **금액**. 비율 자동 계산 아님 |
| 상태 | `완료` 또는 `취소` |

금액은 비워 두지 말고 0을 입력합니다. `12,000`처럼 정상적인 천 단위 구분은 허용합니다. 날짜가 Excel 날짜형이면 텍스트로 변환하고, 수식은 값으로 붙여넣습니다.

**한 주문당 한 행**입니다. 동일 주문의 여러 상품 행을 단순히 중복 제거하지 않습니다. 복수 상품·부분환불·플랫폼별 원본 열 이름은 실제 고객 양식에 맞춰 별도 합의할 사항입니다.

## 계산 범위

- 완료 주문: `수량 × 판매단가 − 할인액 + 배송비 − 수수료`
- 취소 주문: 내역에는 남기되 합계에서 제외
- 예상 정산액은 **순이익, 세금 신고액, 실제 입금액이 아닙니다.**
- 매입비·부가세·배송 원가·부분환불·플랫폼 정산 주기는 계산하지 않습니다.
- 오류가 한 건이라도 있으면 전체 결과의 다운로드를 차단합니다. 잘못된 행을 조용히 버리고 그럴듯한 합계를 내지 않습니다.
- 결과 XLSX는 기존 행 수정 시 다시 계산할 수 있는 수식과 최초 결과 캐시를 포함합니다. 행을 추가·삭제하면 앱으로 다시 처리하세요.

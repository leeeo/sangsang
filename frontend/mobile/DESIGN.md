# 상부상조 앱 디자인 기준

## 1. 제품과 방향

기존 Flutter Material 3 앱을 개선한다. 새로운 금융 대시보드가 아니라
경조사에서 누구와 어떤 마음을 주고받았는지 기억하는 개인 기록장이다.
기존 `AmountText`, Provider, LocalStore, 이름 기반 관계 집계를 재사용한다.

기존 암묵적 시스템은 보라색 `#6366F1`, 차가운 배경 `#F1F5F9`, 흰 카드,
12~20 반경과 16 간격이었다. 홈·입력·내역·사람·분석마다 같은 스타일을
직접 반복했고, 보낸 금액을 빨간 손실처럼 표시하며 잔액을 주인공으로 삼았다.
이번 개편은 따뜻한 바탕과 짙은 녹색, 읽기 쉬운 방향 표시로 이를 대체한다.

### 용어 계약

| 저장/API 값 | 화면 표현 |
|---|---|
| expense | 보낸 마음 |
| income | 받은 마음 |
| transaction | 기록 |
| transaction form | 마음 기록 |
| transaction list | 주고받은 기록 |
| relationship | 함께한 사람 / 관계(입력 항목) |
| analytics | 마음 돌아보기 |
| balance | 주고받은 차이 |

금액은 원 단위이며 돈의 이동 방향은 글자·아이콘으로 표시한다.
주고받은 차이는 채무나 정산 상태가 아니다. 관계의 양수 차이(given-received)와
월 요약의 양수 차이(income-expense)는 서로 반대이므로 원본 계산을 바꾸지 않는다.
`정산 완료`, `내가 더 줌` 대신 중립적인 설명을 사용한다.
저장된 enum, JSON 백업 스키마, category ID, 서버 API는 그대로 유지한다.

## 2. 색상

코드의 단일 원본은 `lib/core/app_theme.dart`의 `AppColors`다.

| 토큰 | 밝은 화면 | 역할 |
|---|---|---|
| primary | #285C50 | 주요 동작·선택 |
| canvas | #F6F5F0 | 따뜻한 배경 |
| surface | #FFFFFF | 입력·요약 표면 |
| ink | #243C34 | 기본 글자 |
| muted | #5F7067 | 보조 설명 |
| line | #DCE3DC | 구분선·입력 테두리 |
| soft | #E8EEE7 | 선택·아이콘 바탕 |
| sent | #526789 | 보낸 마음, 손실/오류 색 아님 |
| received | #28675A | 받은 마음 |
| danger | #B33F3D | 삭제·오류만 |

다크 모드는 시스템 설정을 따른다. 배경 #17231F, 표면 #22332C,
글자 #ECF1EA, 보조 #B6C4BA, 주요색 #A4CBB3, 보냄 #B3C6E7, 받음 #A4CBB3.
안내·아이콘 바탕(primaryContainer)은 밝은 화면 soft, 어두운 화면 #334B40이다.
다크 구분선은 #43554A, 오류 글자는 #FFB4AB다. FAB는 primary 바탕·onPrimary 글자이며 그림자 없이 표시한다.
입력 경계는 장식용 구분선과 분리한다: 밝은 화면 #7B8B80, 어두운 화면 #85998A.
입력면과 경계는 3:1 이상, 보조 글자와 배경은 4.5:1 이상을 유지한다.
레이아웃 색은 Theme ColorScheme을 사용하고 방향색은 밝기에 맞춰 선택한다.

## 3. 글자

새 폰트 의존성을 추가하지 않고 플랫폼의 한국어 시스템 폰트를 사용한다.
본문 16~17, 보조 14, 제목 20~24, 주요 금액 28~32.
버튼·표제는 600, 주요 숫자는 700. 금액에는 tabular figures를 적용한다.
한국어 긴 이름·분류는 줄바꿈/말줄임으로 처리하고 입력 라벨은 항상 보인다.

## 4. 배치와 간격

- 기본 간격 4/8/12/16/24/32. 작은 화면 좌우 20, 폼 좌우 20.
- 휴대폰은 한 열. 넓은 창은 가운데 최대 960, 폼 최대 640.
- 스크롤 주체는 화면별 목록 하나. 폼은 키보드를 피하고 하단 버튼까지 스크롤 가능하다.
- 홈·기록·사람·돌아보기 네 목적지는 동일한 하단 NavigationBar로 접근한다.
- 모바일 390, 작은 폭 320, 큰 글자 1.5배, 넓은 창 1440에서 검증한다.
- 홈은 받은/보낸 마음을 나란히 보여주고 최근 기록과 다음 행동으로 이어진다.
  차이를 수익처럼 크게 띄우지 않는다.

## 5. 재사용 구성요소와 상태

| 구성요소 | 상태·계약 |
|---|---|
| AppNavigation | 홈/기록/사람/돌아보기, 현재 위치 표시, 같은 목적지 재탐색 없음 |
| PageBody | 최대 폭·SafeArea, 내용의 스크롤 소유권 보존 |
| AppEmptyState | 아이콘·무엇을 할지 설명·관련 행동 버튼, 검색 결과 없음과 최초 빈 상태 구분 |
| AppErrorState | 실패 안내·재시도, 빈 내역으로 위장하지 않음 |
| FormExitGuard | 수정한 폼의 이탈 확인, 계속 작성/버리기 선택, 저장 중 이탈 방지 |
| DelayedSpinner | 상태 문구와 고정 공간은 즉시, 회전 표시는 1초 이상 대기할 때만 |
| AmountText | 원 단위·방향 의미·tabular figures, 적자/흑자 색 구분 금지 |
| Material 입력/선택/버튼 | 기본·선택·포커스·비활성·로딩, 누르기 영역 최소 48 |
| 기록 타일 | 이름 우선, 분류·날짜, 방향 텍스트, 금액, 삭제 확인 |

기존 Material 기본 컨트롤을 사용해 키보드·접근성 상태를 유지한다.
주요 구성요소 상태는 실제 Flutter 렌더링 테스트로 먼저 검증한다.
장식용 emoji 아이콘은 Material Icons로 대체한다.

## 6. 동작

과도한 장식 애니메이션은 추가하지 않는다. Material의 선택·누르기·경로 전환을 사용한다.
화면 전환 후 목록·월 집계를 다시 읽어 오래된 필터·월이 남지 않게 한다.
저장 중 중복 제출 방지, 0원/잘못된 금액의 인라인 오류, 삭제 전 확인을 제공한다.
작성한 폼은 뒤로 가기 전에 확인하며, 저장 성공은 확인 없이 닫힌다.
초기 기록장 열기 실패도 재시도할 수 있다. 홈은 불러오는 동안 요약 카드의 자리를 유지한다.
필터는 새로고침·저장 후에도 유지한다. 목록에 남은 항목이 있으면 더 보기로 접근한다.

## 7. 표면과 깊이

톤 차이와 여백을 기본으로 한다. 카드 20, 입력 12, 작은 상태 바탕 8 반경.
테두리는 입력과 구분선에만 사용하며 카드 가장자리 색으로 선택을 표시하지 않는다.
강한 보라색 그라데이션·빨강/초록 손익 신호·숫자 경쟁 요소를 사용하지 않는다.

## 8. 접근성·범위·검증

- 최소 터치 영역 48, 읽기 가능한 대비, 시스템 글자 크기·다크 모드, 한국어 날짜.
- 오류는 문장으로 설명하고 스피너만 남지 않도록 재시도 경로를 제공한다.
- 검증 대상: 첫 프로필, 홈 빈/채움, 기록 입력·검증 오류·방향 변경·저장,
  기록 필터·새로고침·삭제·검색/페이지, 사람 검색·추가·동일 금액, 월/추이, 백업 안내.
- SQLite·서버 계약·JSON 복원 호환을 유지한다. CSV는 사용자용 방향 표현을 바꾼다.
- 서버 로그인·회원가입은 보존 경로이며 기능·권한을 바꾸지 않는다.
- 광고는 기존 위치·정책을 유지하며 실제 광고를 클릭하지 않는다.
- Android 에뮬레이터와 Flutter 렌더링/동작 테스트를 사용한다.
  실제 Android/iOS 기기·스토어 배포와 웹 Lighthouse 평가는 이번 로컬 Flutter 검증과 구별한다.
